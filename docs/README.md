# Documentation

The `/docs` directory is the home of all architectural, design, and conceptual documentation for the system. Documentation is a first‑class component and evolves alongside the codebase.

## Purpose

- Define the system architecture and its components.
- Describe the model ecosystem and specialization strategy.
- Document project‑specific AI profiles and rules.
- Capture design decisions and rationale.
- Provide user‑facing teaching and learning guides.
- Specify coding standards for all components in the system.
- Record the technologies, frameworks, runtimes, and libraries used.
- Maintain specifications for embedded AI capabilities.

## Structure

Documentation includes:

- Architecture documents describing the runtime, agents, profiles, and tools.
- Design specifications covering model roles, memory systems, and learning flows.
- Coding standards defining conventions for structure, style, naming, and patterns.
- Technology specifications detailing the platforms, runtimes, and dependencies used.
- Profile definitions outlining per‑project rules, constraints, and examples.
- API references for internal interfaces and extension points.
- Guides for onboarding, teaching the AI, and adding new models.

## Conventions

- All documents use fully linted Markdown.
- Diagrams appear as vector assets when possible.
- Each document begins with a summary and scope section.
